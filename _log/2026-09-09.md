## Software engineering
1. Spent a bit of time focusing on backtracking today. This is an interesting technique in that it's *sort of* a combination of two different data structures working in tandem. How might systems thinking apply to this? I want to think about this carefully, because I'm worried that I'm applying the hammer of systems thinking to every nail I'm seeing.
2. Still, there's a characteristic way of thinking here: the major component here is determining the way data flows through the algorithm. DFS, BFS, all of these things: they're just patterns of traversal.
3. Some questions when thinking about algorithm puzzles:
    * *How does the data flow?* If we have a linear data structure then the flow is straightforward. A graph or a tree present different ways of having data flow through an algorithm. This is where edge-cases have to be carefully defined.
    * *How is the data processed*? The algorithm itself has this role. Given a new piece of data, how ought it be used? Is it accumulated? Does it store something? Must it be verified?
    * *How does processing change the flow of data?* If I decide to, say, reject a decision, how does this change the flow of data through my structure? Is there any feedback?
    * Given the mechanism that controls data flow and data processing, *where are the boundaries of these mechanisms and how do they interact*? 
    * How does scale manifest? Can I trade resources (space or time) for efficiency?
