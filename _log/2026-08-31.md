## Software engineering
1. Drilled data strutures and algorithms. 
    * An important concept in solving these: **invariants**. An invariant is a statement about the program that is guaranteed to be true at any particular time. Whilst the values can change, the meaning of the property of the state will *always* be true.
    * Invariants are essential to thinking about problems on the basis of correctness, connecting the data structure with the algorithm in a way that you can reason about exactly what your algorithm does. 
    * There are *data structure invariants* and *algorithm invariants*. The first is a property of the data structure that you use, whereas the second is a state that is maintained throughout the algorithm. Essentially, data structure invariants maintain a property for you. Your job, as a an algorithm designer, is to maintain a particular useful state through the algorithm.
    * The art to a lot of this stuff is to figure out how to describe your structure as *precisely* as possible. It's like doing pure mathematics again!
    * Interestingly, I find that my ability to come up with algorithms and solve the problem conceptually to be much better than my ability to actively implement a perfect version of the problem. This is a *genuine* weakness, and one that comes from focusing on theory more than execution. 
2. I've been studying algorithms on and off during the last few months. Nowhere near with the dedication that I'd have wanted to, but bits and pieces. I'm not really starting from zero. However, I wouldn't call myself strong at algorithms. Not just yet. Let's go hard on this front.
