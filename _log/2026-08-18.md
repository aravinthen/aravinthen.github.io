## Systems
1. The basic idea of docker is still fresh, but just for revision purposes let me transcribe my shitty notes from back then:
    * A **container** is a package that contains an application, code and tools. Containers are started through the docker client and are managed by the Docker daemon.
    * A **dockerfile** is a text file required to make an image. 
    * An **image** is a blueprint used to build a container. Docker images are built out of a stack of read-only layers. It is important to note that every command in a dockerfile creates a new layer in the image. There is also an additional Copy-on-Write layer (CoW) that allows for changes to be made if an application modifies a file. If a container crashes, it's writable layer is destroyed.  
    * A **registry** is where you find and share images.
2. Docker is not a virtual machine: you don't have a full operating system to deploy. What you *do* have, however, are
    * Namespaces, which give the container a private view of the system, and
    * Control groups, which limit hardware resources 
3. Volumes are used as persistent data stores for containers.
