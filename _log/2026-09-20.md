## AI safety
1. I'd like to do a bit more research on my end to support the study I'm doing for BlueDot Impact. (internet is also patchy)
2. Now *this* is a useful paper! The goal here was to design a specific set of reinforcement learning environments that would demonstrate AI safety failures. Not only is this a pretty useful description of what could go wrong in an RL setting, it's also a nice example of environmental design: setting up a specific, simple problem that will minimally show what could go wrong when RL is used.
3. Something else I've found useful here is the explicit listing of fields of AI technical safety that *aren't* discussed in the paper. These are
    * Interpretability, which I've been hearing a *lot* about, 
    * Multi-agent problems, which is something that has come up quite a bit over the last few days,
    * Formal verification, which provides mathematical guarantees for various training settings, 
    * Scalable oversight, the ability of an AI to scale and solve more complex problems without requiring human approval
    * reward learning problems, which I've already looked into from *Concrete problems in AI Safety* by Amodei et al.
4. The interesting here is the introduction of a reward funtion (normal RL stuff) and a safety performance function - this is a second reward signal that is hidden from the agent but captures inner alignment. See that? I have a new language for describing this stuff. Awesome!
5. I like this new addition, even though the authors state that it might be controversial given that the agent is being evaluated on a problem it isn't actually aware of. There's a chicken and egg problem here, though: if I want an agent to perform safely, but I don't give it a means to evaluate its performance on the task, then how am I supposed to build in the appreciation for safety within the agent itself? 
6. What *could* be the solution here is to explore training algorithms that maximise safety in general. I'm sure that I'll be coming onto this sooner rather than later. 
7. Some of the problems described here are *damned* hard. Each of these are subdisciplines of reinforcement learning unto themselves. I'm not going to list all of these, but the new ones are
    * Interruptibility: stopping and overriding an agent at any time. However, we don't want to include interruptibility as a feature of the agent: it shouldn't be something that the agent learns to work with or anticipate - it's only really meant to be an external, "unnatural event". How do you train an agent without giving it knowledge of interruptibility?
    * Absent supervisor: it would suck if an agent acted differently based on whether or not it was being supervised. I means, humans do it too, but... - wait, what? No, this shouldn't be encouraged.
    * Self-modification: this can be super dangerous. It's also really important as a means of allowing recursive development. How can we support safe behaviour in settings where agents have this capability?
    * Robustness to adversaries - how can we train agents to operate safely when there are adversaries about? I spent a lot of time thinking about this and I'm convinced that if this problem isn't solved, AI will become prone to feedback loops like arms races that cause enormous destabilization before inevitably falling apart. 
8. A summary of the environments:
    1. Specification problems: where the *reward* function and the *performance* function differ from each other. 
        * Safe interruption: an agent on a grid has the option to interfere with an interruption mechanism. I'm personally not too convinced by this experiment, but I see the main benefit here in that RL algorithms themselves have different behaviours based on how they incorporate information from the exploration policy.
