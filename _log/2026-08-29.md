## Reasoning
1. I'm probably going to be less thorough with my notes on this book. I don't want to recreate all of the content from scratch, so I'll likely be listing important concepts that i want to have memorized.  
2. **Benchmark evaluation**: A more quantitative approach where AI is set up on a particular collection of standardized tasks. 
3. **Judgement-based evaluation**: using human or LLM feedback to rank answers specifically.
4. It really is no wonder that mathematics become a prime training ground for LLM reasoning. I was doing some mathematics puzzles today and made a few errors in reasoning, all based around the fact that I was just getting distracted. LLMs don't get distracted from the task at hand...
5. Chapter 3 isn't particularly challenging - anybody who has used python for a while ought to be able to build verifiers like this. Key lessons here are careful, efficient data-cleaning and the use of `sympy`. In fact, outside of the generation function, most of the work here is pretty much based around string processing techniques. 
6. Chapter 4 is where things become interesting. The generic way of looking at this is by thinking about how a trained model that is already capable of reasoning can augment it's own reasoning. 
    * **Chain of thought**: where an AI is essentially prompted to explain it's reasoning.
    * **Self-consistency**: A model generates multiple responses and selects the most frequent one. Hm... from a cursory search, it looks like this is just where you generate multiple reasoning paths to solve a problem. You then aggregate the final answers - **the answers only** and then pick the answer that the model arrived at most frequently. 
    * Iterative self-refinement, where a model is given it's own reasoning as input and repeatedly makes improvements to it's own work.
7. The basic idea here is that any solution that causes the AI to generate more tokens is one that makes use of inference-time scaling. 
8. The cool thing here is that these techniques seem to be quite effective even for very small models...
9. Why is it that *using* tokens appear to improve the result? Presumably, by forcing the model to use more tokens, the necessary attention weights are better engaged...? It's almost as though each token is operating as a small bit of memory - *oh, like working memory!* No idea if this is true, but I'll do some reading on this.
10. Raschka notes that this could actually be a dangerous technique that leads to overthinking. This, presumeably, is where the previous ideas of treating language generation as trajectory generation is useful.
11. Output diversity can be controlled by temperature scaling. The temperature scaling, as I read about a few weeks ago, manifests in the post-processing of the final neural network output where the concatenated context vectors are mapped to a word in the full vocabulary. Increasing the temperature of the softmax function can make it so that the final probability vector is more uniform. Literally could have skipped this section. This right here was once a field I was trying to master. :) 
13. Now, we're on Chapter 5. The interesting bit about this is the scoring system, which is... actually really straightforward. The technical difference that is actually being discussed here is the difference between a verifier (where you know the true answer to a question) and a scorer (where you need to provide some metric of quality). 
14. "*Probabilities describe how likely an event is before we observe data... likelihoods measure how well a specific model explains observed data." - This is a nice summary of an idea I've unironically struggled to pin down myself. 
15. I'm not convinced by the power of using log probabilities as a scorer. What if the model sucks? What if it's confident about something that is totally wrong? I get that this is a means of implementing decision gates, but I feel like trusting a model to score itself is - never mind, just saw the results. That... is significantly more impressive and I'm surprised that works. From a safety perspective though, I wonder how it could go wrong. 
16. **Log-prob scoring**: Where you assess the internal confidence of a model by summing up the log probabilities of every token it has generated. This is one way of generating these values: you can find the average of the log probabilities instead. You can also calculate the "perplexity", which is the exponent of the average. 
17. Technical point: you use logprobs to avoid numerical underflow and for stability purposes. 
18. The core loop of self-refinement:
    1. Generate an initial prompt, 
    2. Allow the model to assess its own input - essentially, pipe its own input into the context alongside a critique template.
    3. Compute token-level confidence scores using logprobs.
    4. Consume the feedback promp to correct its output.
