4. Oh, hold that thought. There's something new here: KV caching. This is probably my first real introduction to inference performance. **KV Caching** is when intermediate values are reused at each step of the text generation process. The book doesn't really go into depth about this, but the basic idea is that
    * The entire input prompt is processed, with QKV fully calculated. 
    * The initial K+V matrices are saved into GPU memory. This is the initial pass of the KV cache.
    * When generating a new token, the model only computes Q, K, V for the single token.
    * New K and V vectors are appended to the cache.
    * The attention mechanism calculates the dot product with the new query against all keys and values.
    * Normally, you pass in every generated token before you obtain the next prediction. The calculation goes like T1, T1T2, T1T2T3, T1T2T3T4... notice that T1 is repeatedly processed.
    * KV caching makes it so that T1 is generated once and it's key/value matrices are stored. This means that it need only be generated once.
    * The sanity check described here is really good. I need to start building up the kind of experimental intuition that allows for this kind of thinking.
