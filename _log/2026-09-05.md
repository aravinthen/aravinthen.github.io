## Software engineering
1. I'm slowly trawling through graph algorithms. As mentioned before, there are some essential patterns and points that are necessary when working with these data structures. I know that all LeetCode problems can be boiled down into a subset of patterns but it's quite nice to discover this myself. :)
2. I ought to write a blog post soon - Learning from LeetCode. The basic algorithmic thinking patterns that are necessary to solve these problems seem general: they represent a core set of thinking patterns necessary to reason with deep precision regarding computational objects. There must be a condensed kernel of thought necessary to really understand what's going on here.
3. The essence of this kind of work is *systems thinking*. What I've been fundamentally doing over the last week as been 
    1. Integrating different functional components in a safe, highly defined way, 
    2. Having the outputs of those functional components provide a well-scoped emergent output,
    3. Managing invariants in stocks and flows to solve the problem as efficiently as possible.
4. Damn, this realisation has completely changed my view of software puzzles in general. I've gone from thinking that this is just mathematical know-how to wondering how deliberate practice can actually expand my general ability to solve problems *outside* of algorithms.
